# Newsforge

用 AI 对话造一个**属于你自己的每日新闻站**。纯静态、零代码、零成本、零运维。

每天早晨，AI 助手自动抓取你关心的信源、写成摘要，经你确认后部署到 Cloudflare Pages 上。

## 它是什么

Newsforge 不是一个现成的新闻网站，而是一个**建站模板**：你告诉 AI 你想看什么（科技、开源、球鞋、园艺……任何领域），它帮你把网站搭起来、把定时任务建好。之后每天自动更新，你什么都不用管。**全程不用写一行代码**——你的工作只是做选择题、点鼠标。

## 花多少钱

**零。** Cloudflare Pages 免费托管，不绑定域名的话直接用 `*.pages.dev` 子域名。唯一的成本是你自己的 AI 订阅（本来就有）——默认路径下，站内所有 AI 工作都由你的 AI 助手完成，不调用任何付费 API。（还有一条备用的全自动路径，需要自备 LLM API key，见下文「两条运行路径」。）

## 仓库会长多大（以 10 个模块为例）

按每天约 64KB 的 edition 数据估算：

| 图片策略 | 仓库年增量 | 说明 |
|---|---|---|
| b64 进 git | 约 100MB/年 | edition 23MB + 图片 76MB；git 历史只增不减，3 年约 300MB |
| **R2（默认）** | 约 23MB/年 | 只有 edition 进仓库；图片存 R2（约 76MB/年，免费 10GB 额度内零成本） |

结论：R2 模式下仓库一年只长 20 多 MB，十年也就 200 多 MB，GitHub 的 1GB 警告线很远。不用为体积焦虑。

## 开始之前：你需要什么

1. 一个 **GitHub 账号**（存放网站代码）
2. 一个 **Cloudflare 账号**（免费，托管网站）
3. 一个 **Muse**（或者其他支持文件操作、定时任务、GitHub 推送的 AI 助手）——它负责和你对话、搭建网站、每天自动更新

## 完整搭建流程

全程约 40 分钟，其中约 30 分钟是和 AI 聊天做选择题，10 分钟亲手点鼠标。

### 第一阶段：准备（5 分钟）

你需要 3 样东西：

1. 一个 **GitHub 账号**（存放网站代码，公开/私有仓库都可以）
2. 一个 **Cloudflare 账号**（免费，到 [dash.cloudflare.com](https://dash.cloudflare.com) 注册）
3. 一个 **AI 助手**（推荐 Muse App；其他支持文件操作、定时任务、GitHub 推送的 AI 助手也行）——它负责和你对话、搭建网站、每天自动更新

### 第二阶段：建仓库（2 分钟，亲手做）

1. 在本页面点右上角 **Use this template** → **Create a new repository**
2. 填仓库名（比如 `my-daily-news`），选 Public 或 Private，都行
3. 点 **Create repository**——这一步只能你亲手做，AI 建不了仓库

### 第三阶段：让 AI 帮你建站（约 30 分钟，全是选择题）

1. 进你的新仓库，打开 `docs/ONBOARDING.md`，点右上角的 **下载按钮（↓）**，把文件存到手机/电脑上
2. 打开 Muse App，新开一个对话：点输入框旁边的 **附件按钮（➕/📎）**，选中刚下载的 `ONBOARDING.md` 传上来，再输入一句话："按这个文件帮我建站"，发送
3. AI 会按顺序问你（每题先给推荐，你只管选）：
   - **网站基本信息**：叫什么名字？一句话介绍？有没有自己的域名？目标读者是谁？你在哪个时区？
   - **选模块**：你关心哪些领域？（科技、开源、球鞋、园艺……任何领域都行；模板自带一个"赛博风向"示例模块照着抄）
   - **定信源**：每个模块从哪抓？AI 会按领域推荐，你也可以指定（RSS、博客、论坛、官方文档都行）
   - **筛选要求**：有没有不想看的敏感话题？摘要多长？一天几条？
   - **图片存哪**：默认 **Cloudflare R2**（推荐，仓库不膨胀）；也可以选 b64 进 git（零配置）。选 R2 的话跟着走：
     1. 你亲手在 Cloudflare 建 R2 bucket（`xxx-images`）
     2. 开公网访问（正式站推荐绑自己的图片域名，如 `img.example.com`）
     3. 建 API token（Object Read & Write，只限这个 bucket）——**Secret 只显示一次，当场复制**
     4. 把 endpoint、bucket 名、公网地址、Access Key、Secret 发给 AI（直接发聊天里就行，它会立刻存进本机安全文件，不进仓库）
     5. AI 冒烟测试传一张图、亲手打开看一眼，确认没问题
   - **Telegram 订阅**（可选，默认关）：要不要每天把头条推送到 Telegram 频道？要的话按指引找 @BotFather 建 bot
   - **主题风格**：喜欢浅色还是深色？（都支持，一键切换）配色、logo 按你的 taste 来，不套模板默认
   - **抓取策略**：默认每天抓一次，要不要调？
   - **纠错机制**：读者报错走什么渠道？
4. 问完，AI 会在你的仓库里生成 `site.json`（站点配置）、`modules/`（你的模块）、主题样式，然后本地构建一次给你看效果

### 第四阶段：上线到 Cloudflare Pages（10 分钟，亲手做）

1. 登录 [dash.cloudflare.com](https://dash.cloudflare.com) → 左侧 **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
2. 按提示授权 GitHub，选中你第二阶段建的仓库，点 **Begin setup**
3. 构建配置（照抄）：
   - 构建命令：`npm install && node pipeline/run.js --render-only && npx --yes pagefind --site dist`
   - 输出目录：`dist`
   - 环境变量：点 **Add variable**，`NODE_VERSION` = `20`
4. 点 **Save and Deploy**，等 1-2 分钟构建完成
5. 打开分配给你的 `xxx.pages.dev` 地址，网站上线了 🎉
6. （可选）绑自己的域名：Pages 项目里 **Custom domains** → **Set up a custom domain**，按 Cloudflare 的提示去域名商加一条 DNS 记录

### 第五阶段：定时任务（AI 帮你建）

回到和 AI 的对话，让它建 3 个定时任务（模板在 `crons/` 里，它会照着配）：

| 任务 | 时间 | 做什么 |
|---|---|---|
| 每日构建 | 每天凌晨（你定，比如凌晨 5 点） | 抓取 → AI 编辑 → 生成今日版本 → 本地构建，**暂存不推送** |
| 推送确认 | 构建完成后 1.5 小时 | AI 向你汇报今日摘要（各模块几条新内容、头条标题），你回"推送"才上线 |
| 信源探针 | 每天凌晨 | 检查信源是否存活，连续 3 天挂掉的自动禁用并通知你 |

### 第六阶段：日常使用

之后每天早晨，AI 会准时汇报："今日 X 个模块更新，Y 条新内容，头条是……"，你点个头（回"推送"）网站就更新了。不想每天确认也可以设成全自动。

随时想加新模块、换信源、调风格，直接跟 AI 说就行，改完它会本地验证再推送。

## 里面有什么

- `pipeline/` — 抓取 + 构建管线：`run.js` 只做调度，`lib/` 下分模块（`utils` 基础工具 / `fetchers` 信源抓取 / `edit` LLM 编辑 / `images` 图片管线 / `render` 静态渲染 / `r2-images` R2 图片上传）
- `modules/cyber/` — 一个示例模块，照着它就能写自己的模块
- `docs/` — 写给 AI 助手看的安装剧本和手册（`ONBOARDING.md` 是入口，`R2-IMAGES.md` 是图片存 R2 的完整指南）
- `crons/` — 定时任务模板：每日构建、推送确认、信源健康检查

## 两条运行路径（先看懂这个）

**路径 A：AI 助手编辑（默认，零 API 成本）。**
每天的抓取由 `npm run fetch`（=`node pipeline/run.js --fetch-only`）完成，
编辑（选头条、写摘要点评）由你的 AI 助手按 `docs/SCRAPING.md` 和各模块 `editorial` 口径手工完成，
最后 `npm run render` 生成静态页面。这是模板设计的默认路径，不调用任何付费 API。

**路径 B：LLM API 自动编辑（备用）。**
设置 `LLM_API_KEY`（及可选 `LLM_BASE_URL` / `LLM_MODEL`，默认兼容 DeepSeek 接口）后，
`npm run build` 会走"抓取 → LLM 自动编辑 → 渲染"全自动流程，适合 GitHub Actions 无人值守运行。
这条路径要花你自己的 API 费用，默认关闭；`--skip-llm` 可强制跳过。

## 内容来源与署名

- 每条新闻都保留**原文链接和来源名称**，点击标题即跳转原文；摘要为 AI 改写、仅供参考，不能替代原文。
- 抓取时尽量做个有礼貌的访客：可识别的 `NewsforgeBot/0.1` UA（个别拒绝机器人 UA 的站点回退浏览器 UA）、请求超时与并发上限、每天只抓一次。信源是你在安装时亲手逐个挑选的——如果某个站点明确不欢迎抓取，请手动把它从信源列表里移除。
- 版权提醒：不同国家/地区对"新闻摘要"的合理使用规定不同，上线前请自行确认你的做法符合当地法律；如有来源方要求删除，请配合下架。
