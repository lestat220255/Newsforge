# 抓取策略手册（给 AI Agent 看）

> 安装第 7 步用：把每条策略用大白话讲给用户听，逐条问"改不改"。
> 默认值是久经考验的配置，用户说不改就直接用。

## 1. 信源类型

| 类型 | 说明 | 默认 |
|---|---|---|
| RSS | 最稳定，优先 | 开 |
| weblist | 无 RSS 的列表页，cheerio + CSS 选择器抓取 | 开 |
| GDELT | 全球新闻数据库，**补充源**：主力候选不足 10 条时才启用，结果标 [补充源] | 开（降级） |
| Mastodon 趋势 | `/api/v1/trends/links` 免认证，同 GDELT 降级机制 | 开（降级） |
| v2ex | V2EX 节点 API（`node` 参数，如 `node_name=share`），社区帖子 | 关（按需） |
| reddit | Reddit 子版块 JSON（`sub` 参数），需注意 429 限流 | 关（按需） |
| govuk | 英国政府官网搜索（`query` 参数），官方政策源 | 关（按需） |
| huggingface | HuggingFace 热门模型榜（开源/AI 模块用） | 关（按需） |
| github | GitHub releases / trending（开源模块用） | 关（按需） |

> 抓取 UA：默认 `NewsforgeBot/0.1`；`BROWSER_UA_HOSTS`（`pipeline/lib/utils.js`）里的域名
> （如直接拒绝机器人 UA 的站点）会自动改用浏览器 UA。加新站时如果被 403/连接重置，
> 先把域名加进这个集合再调选择器。

抓取安全上限：单个响应体超过 **5MB** 直接丢弃（`fetchText` 内置），超时 25 秒（探针 20 秒）。

## 2. 新鲜度

- 头条：48 小时内的新闻，无够格新内容则**整版隐藏**（不凑数）
- 次条：按发布时间倒序，超 72 小时一律不收，宁可空着
- 每板块每天 1 头条 + 最多 5 条次条（不 AI 凑数）

## 3. 去重

- 跨天 URL 去重：上一期已发布的 URL（去 query/hash/尾斜杠后比较），不再作为新候选入选
- 全站文章索引按详情页 URL 去重（沿用板块会复用 URL，不去重会重复）

## 4. 沿用规则

- 无够格新内容时可整版沿用上一期，标记 `carried:true`，前端显示"沿用前期版本"
- 连续沿用不得超过 1 天；第二天仍无新内容则隐藏该板块
- 沿用内容不进"今日最值得看"，不进 Telegram 订阅推送

## 5. 信源分级 T1/T2/T3

- **T1**：官方一手信源（如公司官方博客、监管机构），可单信源直接入选
- **T2**：常规可信媒体，默认级别
- **T3**：利益相关方官方信源（如涉自身争议的公司官网）——只作"当事方回应"引用，**永不单独作为事实依据**
- 涉自身争议的当事方口径自动降为 T3

## 6. 摘要铁律（强烈建议保留）

- 摘要每句话必须在原文有直接对应，找不到就不写
- 原文未提就写"原文未提"，绝不脑补
- 人名、职务、数字、时间与原文完全一致
- 摘要只放信息，观点只进点评/分析；AI 观点必须明确标注为观点
- 待确认内容：不做头条、排序沉底、不打 🔥

## 7. 可信度徽标

- `unverified` → 灰色「待确认」
- `multi_source` → 绿色「多信源」（待确认时 multi_source 必须为 false）
- 🔥 只打真正热点，待确认条目永不带 🔥

## 8. 时区

- 无时区的时间字符串一律按用户时区解析（默认北京时间 +08:00），不直接 `new Date(iso)`——否则本地和 Cloudflare Pages（UTC）排序会不一致

## 9. 信源健康

- 每天探针：串行探测全部源，20 秒超时算未知（不计失败）
- 连续 3 天硬失败 → 自动禁用并通知用户（删条目即恢复）
- 单次超 30% 不可用视为本机网络故障，中止移除
