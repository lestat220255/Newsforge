# 信源探针（每天凌晨）

## 目标
探测全部信源是否存活，连续挂掉的自动禁用并通知用户。

## 步骤
1. 跑 `npm run probe`（=`node pipeline/probe-sources.js`），串行探测 `modules/*/module.json` 的全部源。
2. 规则：
   - 单源 20 秒超时 → 记为"未知"，**不计失败**
   - 连续 3 天硬失败 → 写入禁用列表，构建时自动跳过，**邮件/消息通知用户**
   - 单次超 30% 源不可用 → 视为本机网络故障，**中止移除**，只通知用户
   - 删掉禁用列表条目即恢复该源
3. 向用户报告：可用 X/Y，有新增禁用时说明原因。

## 注意
- 探针只测可达性。weblist 源选择器失效导致"零产出"探针发现不了——如果某模块连续多天零候选，单独提醒用户检查选择器。
- GDELT 类常被限流的源：连续 429 三天才禁用，之前只警告。
